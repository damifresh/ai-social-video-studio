## Additional verified behaviors

- **Sequential guard:** second `/generate` while running returns HTTP 409.
- **A/V sync fix:** narration padded to `speech_dur + 0.25 s` gap so audio matches video timeline/subtitles (verified 78.52 s end-to-end).
- **Audio mix:** narration+music mixed, ducked, loudness-normalized (≈ −15.8 LUFS / −3.4 dBTP, no clipping above limiter target).
- **Subtitle customization:** edited cues/style saved and preserved on re-render; cleared on full regeneration (verified SRT/ASS content).
- **Question-style hook fix:** topics starting with how/what/why… produce natural openings (verified in 9:16 project).
- **Bundled CC0 assets:** procedural music/SFX generated by `scripts/generate_assets.py` with `licenses.json`.
- **Frontend build:** `npm run build` PASS (TypeScript + Vite).
- **Multi-source combine (2026-11-19):** `render_combine()` was exercised with real FFmpeg on a synthetic 16.43 s clip. Two sources with 0.6 s crossfades produced a validated 3.4 s MP4 (`transition.boundaries=[0.6]`, `offsets=[1.4]`); the same two sources as straight cuts produced a validated 4.0 s MP4; a three-source crossfade produced a validated 5.0 s MP4 with `boundaries=[0.5, 0.5]`, `offsets=[1.5, 3.0]`. `validate_render()` passed for every output (720p, H.264/AAC, A/V sync). **Target-duration fix:** the UI's shortest selected Target duration is now sent as `target_duration`; with two 3 s sources and a 5 s target, both fade and cut modes produced validated 5.0 s MP4s with proportional per-source trims, and an over-long target is rejected explicitly. The probe duration equals the requested timeframe. Unit coverage lives in `backend/tests/test_clip_combine.py`; the Electron smoke appends two coloured 3 s MP4s via `POST /projects/{id}/sources`, reorders them, adds a 5 s custom target through the UI, and asserts the cut candidate (`source_combine`, `second.mp4,first.mp4`, 5 s, `target_duration=5`, selected, downloadable, `engine=source-combine/v1`) and the re-combined crossfade candidate (5 s, `fade`). The toggle was verified default-on and persisted to `/projects/{id}` in both smoke modes.
- **Combined-video Export fix (2026-11-19):** reproduced the reported failure directly: `_render_one()` sent combine segments (per-source `0 → duration` ranges) into `render_assembly()` on one source, yielding `ValueError: Assembly segments must be non-overlapping`. It now dispatches `assembly.kind == "source_combine"` to `render_combine()` with the candidate's stored paths, saved order and transition options, with no transcript captions. An isolated `TestClient` run uploaded two distinct 2 s MP4s, combined them, then called `POST /projects/{id}/export-batch`; the job succeeded with one validated 3.42 s MP4 (`source_combine`, `transition.mode=fade`, two sources, no hashtags). Repeating with cuts produced a validated 4.02 s MP4 (`mode=cut`). The manifest records `source_combine`, `combine_sources` and per-item `combine`/`transition` metadata; after the target-duration fix it also records the stored `target_duration` so a re-export lands on the same timeframe. Both the dev and packaged Electron smokes now click **Export** after combining and assert the manifest item's validation, source count and target.
- **Combined-video native resolution + xfade size fix (2026-11-20):** combine output now uses the first ordered source's native canvas instead of cover-cropping to the aspect preset; encode quality is `libx264 -preset medium -crf 18`. A real 1280×720 source produced a validated 1280×720 MP4, and a mixed 1280×720 + 360×640 combine stayed at 1280×720 with the smaller source padded, not cropped. A reported failure (`xfade`: `main parameters (size 1080x1920) do not match ... (size 1920x1080)`) was traced to relying on probe-reported dimensions for pass-through; all inputs are now normalised with `setsar=1,scale=...:force_original_aspect_ratio=decrease:flags=lanczos,pad=...`, which is pixel-identical at 1:1, and a regression test reproduces the stale-probe case (also verified with the exact reported 1080×1920 / 1920×1080 sizes). Probe output additionally carries rotation-aware `display_width`/`display_height`. 56 backend tests and both 25-check Electron smokes pass.
- **No-speech ASR fix (2026-11-20):** a reported `RuntimeError: whisper.cpp produced JSON without segments` during `_job_combine` was reproduced with the bundled whisper.cpp on a pure tone: it exits 0 and writes valid JSON with `"transcription": []`. That is a normal no-speech result, so `transcribe()` now returns an empty transcript with a note instead of raising; `_combine_source_cues()` reports `no speech detected; no captions generated` and the combine succeeds without inventing text. Non-zero exits now retain their stderr for the error message. 60 backend tests pass.
- **No-zoom native previews for single/assembled videos (2026-11-20):** `_video_chain()` was cover-cropping (`force_original_aspect_ratio=increase` + exact crop) for single-source clips and one-clip assembly, enlarging the frame and cutting its edges. Those two paths now use the same native canvas as combine: rotation-aware source width/height, `setsar=1,scale=...:decrease:flags=lanczos,pad=...`, CRF 18/medium, native caption scaling and native `resolution`/`source_resolution`/`resolution_mode` metadata. Only an explicit `custom` crop rectangle is applied; default/edge crop modes no longer change the picture. Combine geometry and the earlier native/xfade/no-speech fixes are untouched. Real 1280×720 renders verified for a single clip and a two-scene assembly; 64 backend tests pass.
